# 🏠 Квартиры · Астана: агрегатор объявлений

Статический сайт для GitHub Pages. Собирает объявления о продаже квартир в Астане и проверенных пригородах с **Krisha.kz** и **OLX.kz**, а затем обрабатывает их:

- отсекает чёрный список посёлков, ЖК и улиц (Талапкер, Кызылсуат…);
- помечает объявления с признаками проблем ЖКХ (привозная вода, септик, печное отопление, «без документов»…);
- склеивает дубли одной квартиры с разных площадок и от разных риелторов;
- считает цену за м² и её отклонение от медианы по похожим квартирам;
- следит за историей цен и ставит бейдж **📉 Снижение цены**.

Избранное, скрытые объявления, статусы («Звонил», «Договорился», «Не брать») и заметки хранятся в браузере. Их можно выгрузить кнопкой **Экспорт** и загрузить на другом устройстве кнопкой **Импорт**.

> Сразу после установки сайт показывает **демо-данные**: вымышленные объявления, чтобы проверить интерфейс. После первого успешного запуска парсера они заменяются настоящими.

## 🚀 Как запустить сайт (пошагово, один раз)

### Шаг 1. Сделайте основную ветку `main`
Код лежит в ветке `claude/trusting-ramanujan-4hocw9`. Удобнее, чтобы он был в `main`.

**Вариант А.** Репозиторий был пустым, и эта ветка стала основной:
1. Откройте репозиторий на GitHub и нажмите **Code → Branches** (или ссылку «N branches» над списком файлов).
2. У ветки `claude/trusting-ramanujan-4hocw9` нажмите ✏️ (**Rename branch**), введите `main` и нажмите **Rename branch**.

**Вариант Б.** У вас уже есть ветка `main`: создайте Pull Request из `claude/trusting-ramanujan-4hocw9` в `main` и нажмите **Merge**.

Проверьте в **Settings → General → Default branch**, что основная ветка именно `main`.

### Шаг 2. Разрешите GitHub Actions записывать в репозиторий
1. **Settings → Actions → General**.
2. В разделе **Actions permissions** выберите **Allow all actions and reusable workflows**.
3. Ниже, в **Workflow permissions**, выберите **Read and write permissions** и нажмите **Save**.

Без этого парсер не сможет сохранять свежие объявления.

### Шаг 3. Включите GitHub Pages
1. **Settings → Pages**.
2. В **Build and deployment → Source** выберите **GitHub Actions**. Не «Deploy from a branch»!

> GitHub Pages бесплатно работает только для **публичных** репозиториев. Если репозиторий приватный: **Settings → General → Danger Zone → Change visibility → Public**. Заметки родителей хранятся в их браузере, в репозиторий они не попадают.

### Шаг 4. Опубликуйте сайт
1. Вкладка **Actions**. Если GitHub спросит «Workflows aren't being run on this repository», нажмите **I understand my workflows, go ahead and enable them**.
2. Слева выберите **Deploy site to GitHub Pages** и нажмите **Run workflow → Run workflow**.
3. Через 1–2 минуты в **Settings → Pages** появится адрес вида `https://<ваш-логин>.github.io/apartnment-searcher/`. Это и есть сайт, его можно отправить родителям.

### Шаг 5. Запустите первый сбор объявлений
1. **Actions → Scrape listings → Run workflow**.
2. Сбор идёт 10–30 минут: между запросами парсер специально делает паузы по 2–5 секунд, чтобы сайты его не заблокировали.
3. После этого сайт сам обновится, и вместо демо-данных появятся настоящие объявления.

Дальше всё работает автоматически: парсер запускается **каждые 2 часа**, сохраняет новые данные и переопубликовывает сайт.

### Если что-то не работает
- **Красный крестик в Actions.** Откройте запуск и посмотрите, на каком шаге ошибка. Сообщение «Permission denied / 403» при push означает, что не выполнен шаг 2.
- **На сайте жёлтая плашка «Не удалось обновить: krisha — 0 объявлений».** Площадка поменяла вёрстку или блокирует серверы GitHub. Сайт продолжит показывать последние сохранённые данные. Попробуйте запуск с домашнего компьютера (см. ниже).
- **Расписание остановилось.** GitHub отключает cron-задачи в репозиториях без активности больше 60 дней. Включите заново: **Actions → Scrape listings → Enable workflow**.

## ✏️ Как редактировать списки и настройки

Все настройки лежат в папке `config/`. Это JSON-файлы, их можно править прямо на GitHub: откройте файл → ✏️ **Edit** → **Commit changes**. Изменения применятся при следующем запуске парсера. Чтобы сразу, запустите **Actions → Scrape listings → Run workflow**.

| Файл | Что внутри |
|---|---|
| `config/blacklist.json` | **Чёрный список.** `localities`: посёлки (целое слово), `complexes`: названия ЖК, `streets`: улицы. Такие объявления выбрасываются при сборе. |
| `config/locations.json` | **Белый список географии.** Астана и разрешённые пригороды с вариантами написания (`aliases`). Всё, чего здесь нет, отбрасывается. Для посёлка можно указать `require_any`: тогда из него берутся только объявления с этими словами (например, проверенные сектора Коянды). |
| `config/stopwords.json` | `utility`: стоп-слова ЖКХ (флаг ⚠). `new_building`: признаки стройки/ДДУ (для «Только вторичка»). `highlight_positive`: слова, которые подсвечиваются зелёным в описании. |
| `config/default_filters.json` | Фильтры по умолчанию: 2 комнаты, до 20 млн ₸, 1–3 этаж, дом от 2000 года, только вторичка. Кнопка «Сбросить к моим настройкам» возвращает именно их. |
| `config/sources.json` | Настройки парсера: максимальная цена сбора (`max_price`, по умолчанию 30 млн, чтобы на сайте можно было расширять фильтр), число страниц, паузы, ссылки поиска на Krisha/OLX. |

**Пример: добавить ЖК в чёрный список.** В `config/blacklist.json`:
```json
"complexes": ["Название ЖК", "ЖК Другое название"],
```

**Пример: в Коянды брать только проверенные места.** В `config/locations.json` у Коянды:
```json
"require_any": ["ЖК Проверенный", "ул. Хорошая"]
```

**Ссылки поиска** в `config/sources.json` можно заменить своими. Настройте поиск на krisha.kz или olx.kz, скопируйте адрес из браузера и вставьте его, а цену в ссылке замените на `{max_price}`.

## 💻 Запуск на своём компьютере (необязательно)

Нужен Python 3.10+.

```bash
pip install -r scraper/requirements.txt
```

```bash
python -m scraper.main
```

```bash
python -m http.server 8000
```

После этого откройте http://localhost:8000. Если просто открыть `index.html` двойным кликом, браузер не даст загрузить данные.

Если площадки блокируют серверы GitHub, парсер можно запускать по расписанию дома (cron или Планировщик заданий Windows) и отправлять данные в репозиторий:

```bash
python -m scraper.main && git add data && git commit -m "data: обновление" && git push
```

Другие команды:

```bash
python -m scraper.main --demo
```

```bash
python -m scraper.main --sources krisha --verbose
```

```bash
python -m unittest discover -s tests -t .
```

`--demo` заново создаёт демо-данные. `--sources krisha --verbose` опрашивает только Krisha с подробным логом. Последняя команда запускает тесты.

## 🗂 Структура репозитория

```
index.html, assets/        — сайт (HTML + CSS + JS без сборки и зависимостей)
config/                    — редактируемые настройки и списки
data/listings.json         — готовые карточки для сайта (генерируется)
data/meta.json             — время обновления и статус площадок
data/price_history.json    — история цен по каждому объявлению
data/raw_listings.json     — кэш «сырых» объявлений парсера (на сайт не публикуется)
scraper/                   — парсер на Python
  sources/krisha.py, olx.py  — модули площадок (новую площадку — новым файлом)
  pipeline.py              — география, ЖКХ-фильтр, дубли, аналитика, история цен
  http_client.py           — ротация User-Agent, паузы 2–5 с, повторы
.github/workflows/
  scrape.yml               — сбор каждые 2 часа + коммит + публикация
  pages.yml                — публикация сайта на GitHub Pages
tests/                     — тесты парсеров и пайплайна
```

### Как устроена обработка
1. **Сбор.** Парсер проходит страницы поиска и для новых объявлений догружает подробности: описание, все фото, координаты. Фото и видео не скачиваются, сохраняются только ссылки на них.
2. **География.** Объявление принимается, только если это Астана или посёлок из белого списка и оно не попадает в чёрный список.
3. **ЖКХ.** Стоп-слова ищутся в заголовке и описании и выставляют флаг `has_utility_warning` с перечнем найденных слов.
4. **Дубли.** Объявления склеиваются при совпадении ЖК/района, комнатности и этажа и разнице площади не больше 1,5 м². Если ЖК не указан, дополнительно сверяется цена (±15%). В карточке показывается минимальная цена и все источники со своими ценами.
5. **Аналитика.** Цена за м² сравнивается с медианой по той же комнатности: сначала в том же районе, если похожих мало — по населённому пункту, затем по региону.
6. **История цен.** При каждом изменении цены в `price_history.json` добавляется запись. Если цена снизилась, появляется бейдж, а если квартира при этом вошла в бюджет, отдельная отметка «вошла в бюджет».
7. Объявления, которые не попадались **4 дня** (`drop_after_days`), удаляются. Если площадка в этот раз не ответила, её старые данные не трогаются.

### Как добавить новую площадку
Создайте `scraper/sources/<name>.py` с классом-наследником `BaseSource`. В нём нужен метод `fetch_list()` и, при необходимости, `fetch_details()`, которые возвращают записи в формате `empty_record()`. Зарегистрируйте класс в `scraper/sources/__init__.py` и добавьте секцию `<name>` в `config/sources.json`.
